## 1. 目的と成功の基準

**目的**
- 自分の感度(振り向きの距離)に近いプロ選手を知り、「自分の設定は変じゃない」という安心と話題にする。
- 感度計算からの流れと、「プロ設定 VALORANT」のような検索の入口にする。

**成功の基準**
- マイ設定にメインゲーム・感度・DPI がある人は、`/pros` を開くだけで近いプロが 5 人見られる。
- 感度計算の結果の下に、その感度に近いプロが 3 人出る(保存しなくても)。
- 数字はすべて一次情報(選手本人・所属チーム)で確かめたもので、出典と確認日がある。

## 3. 画面と流れ(設計 1/4・3/4)

### 3.1 ページ `/pros`(新規・ログイン不要・PC とスマホの両方)

1. **上:あなたに近いプロ**
   - マイ設定にメインゲーム・感度・DPI がそろっていれば、「あなたの振り向き:約 32.5cm」と出し、近いプロを 5 人出す。
   - 各カードに差の一言(4.2)を出す。
   - そろっていなければ、「感度計算でマイ設定に保存すると、近いプロが出ます」と感度計算へのリンク。
2. **下:ゲームごとの一覧**
   - タブ:VALORANT/Apex/OW2/CS2。初期はマイ設定のメインゲーム(4 本になければ VALORANT)。
   - 列:選手名・チーム・DPI・ゲーム内感度・eDPI・振り向き(cm)・マウス・出典。
   - 並び替え:振り向きの短い順(初期)・長い順・名前順。全員を出す(「もっと見る」はなし)。
   - マウスがマウス探しのデータ(`src/data/mice.ts`)にある場合は、`/mouse` へのリンクにする。
   - スマホではカード型(1 人 1 枚)にする。
   - 出典は「出典」というリンク(`target="_blank" rel="noopener noreferrer"`)。URL は表示しない。
   - 各選手に確認日を小さく出す(例:「2026-10 確認」)。
3. **ページの下**
   - 「数字は選手本人・所属チームの公開情報です。変わることがあります(確認日は各選手に記載)」
   - 「掲載を外してほしい場合は、お問い合わせからご連絡ください」(規約の問い合わせ先へのリンク)

### 3.2 感度計算(`/tools/sensitivity`)への追加
- 計算結果が出ているときだけ、結果の下に「この感度に近いプロ」を 3 人(カード)出す。
- 計算中の入力をそのまま使う(保存しなくてよい)。
- 「プロ設定をもっと見る」で `/pros` へ。

### 3.3 そのほか
- ヘッダーの「マウス探し」の次に「プロ設定」を足す(スマホでは折り返す)。
- `/pros` の X 用画像は固定(「ロビラボ プロ設定」+ 対象の 4 ゲーム名)。
- シェア機能、人ごとの画像は作らない。

## 4. 近さの計算(設計 2/4)

### 4.1 振り向きの距離
- 既存の `cm360(dpi, sens, yaw)` と `edpi(dpi, sens)`(`src/lib/sensitivity.ts`)を使う。感度計算ツールと同じ式。
- yaw は `SENS_GAMES` のそのゲームの値。

### 4.2 近い順 `src/lib/pro-match.ts`(新規)
- 差 = |プロの振り向き − あなたの振り向き|
- 並び:あなたのメインゲームと同じゲームの人が先。その中は差が小さい順。同じなら名前順。
- メインゲームが 4 本以外(CoD など)のときは、「同じゲーム」の優先をせず、全員を差の順に並べる。
- 差の一言:差 ≤ 0.5cm は「ほぼ同じ」、それ以外は「あなたより 2.1cm 短い」「あなたより 2.1cm 長い」(小数第1位)。

## 5. データ(設計 2/4)

### 5.1 `src/data/pros.ts`(新規)

```ts
type ProSetting = {
  id: string;              // 例 "valorant-xxx"
  name: string;            // 選手が公に使っている活動名だけ(本名は載せない)
  team: string | null;     // 確認日時点の所属
  game: "valorant" | "apex" | "overwatch" | "cs2";
  dpi: number;
  sens: number;            // ゲーム内感度
  mouse: string | null;    // devices.ts の id(マウス探しにつなぐ)。候補にないマウスは null とし、mouseName に名前
  mouseName?: string;      // devices.ts にないマウスの名前(公式の製品名)
  sourceUrl: string;       // 一次情報:選手本人の X・配信・動画、所属チームの公式ページ
  checkedAt: string;       // YYYY-MM-DD
};
```

- 集め方:実装のとき、一次情報を開いて数字を確かめる。まとめサイト(prosettings.net など)や Wiki は出典に使わない(選手を探す手がかりにするだけ)。一次情報で確かめられない選手は載せない。
- 目安は 1 ゲーム 10〜20 人。集まらなければ少なくても出す(最低 5 人)。
- 更新:移籍や感度の変更は `pros.ts` を直して確認日を更新する。掲載を外すときは行を消す。

### 5.2 DB・サーバー
- 使わない。データは同梱し、あなたの感度との比較はブラウザの中だけで行う。

## 6. エラーのとき・テスト・運営(設計 3/4・4/4)

### 6.1 エラーのとき

| 状況 | 動き |
|---|---|
| マイ設定に感度・DPI がない | 上の欄の代わりに、感度計算で保存する案内とリンク |
| メインゲームが 4 本以外 | 全ゲームから差の順に出す(同じゲームの優先なし) |
| あるゲームのプロが 0 人 | そのタブに「準備中」 |
| マイ設定の値が壊れている | 読み込み時の検証で空として扱う(マイ設定と同じ) |

### 6.2 テスト
- **単体(Vitest)**
  - 振り向きの距離・eDPI が感度計算ツールの値と一致する
  - 近い順(同じゲーム優先 → 差 → 名前)、メインゲームが 4 本以外のときの並び
  - 差の一言の境目(0.5cm)
  - データの整合:ゲームが 4 本のどれか、DPI(50〜64000)と感度が `SENS_GAMES` の範囲内、出典が https でまとめサイト(prosettings.net、liquipedia.net、prosettings.com、settings.gg など)のドメインでない、id が重ならない、マウスの id が `devices.ts` にある、確認日の形
  - 一覧の並び替え 3 種類
- **ブラウザ(本番ビルド)**:マイ設定がない/あるとき、タブと並び替え、感度計算の下の 3 人、スマホのカード表示、X 用画像が 200。
- **公開前**:差分のセキュリティ監査(quick)。外部リンクと表示の安全さ。
- **本人の確認**:載せる選手と数字の一覧。

### 6.3 規約・運営
- `/pros` の下に、出典の考え方と掲載を外す依頼の受け方を書く。
- `docs/ops/moderation.md` に「掲載を外す依頼が来たら `pros.ts` の行を消して公開し直す」を足す。
- 選手の名前は公に使っている活動名だけ。写真・チームのロゴは使わない。
