  - 動いている間、名前を付けた要素はクリックを受けない。短くし(400ms 以下)、何度も押す要素には名前を付けない。`::view-transition { pointer-events: none; }` を入れる。

## 2. コンセプト

### 一言:「なぞって、組み上がる。」

ロビラボは、試合が始まる前のロビー。そこで自分の手(なぞる線)を確かめ、自分のタイプ(ドットのマス)が組み上がり、仲間が集まる。サイトのすべての見た目と動きを、**「線」と「マス」**の 2 つの言葉だけで作る。

| 言葉 | 見た目 | 動き | どこから来たか |
|---|---|---|---|
| 線 | なめらかな光の線(ネオン管)。漢字の書き順・エイムの軌跡・ルーラーの目盛り | 書き順どおりに引かれる(`stroke-dashoffset`) | 今日の文字(KanjiVG の書き順)と、マウスを動かす手 |
| マス | 8px の格子。ドット絵・バー・進み具合・区切り | 1 マスずつ、段で埋まる(`steps()`) | 16 タイプのドット絵(D29)、懐かしいゲーム |

### 3 つの柱

1. **ロビー = 試合の前の待合室**
   - 画面は「待合室の掲示板」。人やタイプは「並んでいる・集まってくる」ように見せる(候補 = プレイヤーの札、16 タイプ = 名簿)。
   - 言葉も待合室に寄せる(例:「今日の文字に挑戦」「仲間が待っています」)。ただし戦場・軍隊の言葉は使わない(設計書のアンチパターン 6)。
2. **線とマスの対比 = 今っぽさと懐かしさ**
   - 線(なめらか・今)とマス(カクカク・懐かしい)を同じ画面で並べ、ぶつけて見せる。曲線のネオンの漢字の横に、カクカクのドット絵。
   - 動きのイージングも 2 種類だけ:線はなめらか(`cubic-bezier(0.2,0,0,1)`)、マスは段(`steps(n)`)。中間の「ふわっ」は使わない。
3. **手で確かめる = 触ると答える**
   - このサイトの道具はどれも「自分の手」の話(なぞる・感度・手のサイズ)。だから、見せ場はすべて**触ると答える**形にする。勝手に動き続けるものは置かない(設計書 2-4 と同じ考え)。
   - 数字は「物の大きさ」で見せる(振り向き 34.6cm は本物の長さの定規、手のサイズはマウスと重ねた実寸の図)。

### 線とマスの使い分けのルール

- 1 画面で「線の見せ場」と「マスの見せ場」は合わせて 1 つまで(ほかは静かにする)。
- 線の光(グロー)は、今日の漢字と見せ場の線だけ。本文・小さい文字には付けない。
- マスの大きさは 8px の倍数だけ(4px は使わない。ドットに見えなくなるため)。

## 3. 見せ場(シグネチャー体験)

5 つ。自動で動くのは S1 の最初の 1 回と S2 の結果の 1 回だけ。ほかは人の操作に答える動き。

### 重さの全体の上限

| 項目 | 上限 |
|---|---|
| 見せ場のために足す JS(gzip) | 全部で 12KB。1 つ 4KB まで |
| 動かしてよい性質 | `transform`・`opacity`・`clip-path`・`stroke-dashoffset`・`filter: blur()`(View Transition の中だけ) |
| 動かしてはいけない性質 | `width` / `height` / `top` / `left` / `box-shadow` / `text-shadow`(光は動かさない。光の強さを変えたいときは、光を付けた重ねの `opacity`) |
| 1 フレームの仕事 | 4ms 以下(Performance パネルで 6× CPU 遅延でも 60fps に近い) |
| LCP | 見せ場の要素を LCP にしない。LCP は最初から見えている文字(h1・説明)にする |
| CLS | 0.02 以下。動く要素は最初から同じ大きさの箱を取っておく |

### S1. トップのヒーロー「今日の文字が書かれる」

- **何を**:今日の漢字を、KanjiVG の書き順の線(`src/data/aim-chars.json` の `strokes`)で、1 画ずつ光の線として引く。引き終わると、文字の縁に D29 の色ズレ(マゼンタとシアンが 1.5px ずれる)が**一度だけ**すっと定まって止まる(点滅しない。WCAG 2.3.1 に触れない)。
- **触れる**(PC):漢字の上にマウスを置くと、カーソルの位置に照準(細い十字と 4 つの角の印)が出る。クリックしたまま最初の 1 画をなぞると、その線がライムで重なり「この感じで全部の画をなぞる」と小さく出る。下の主ボタン「今日の文字に挑戦」へつなぐ。これは試しで、点数は付けない。
- **触れる**(スマホ):漢字の下に `secondary`「1 画なぞってみる」。押したときだけ漢字の箱が指の入力を受ける(`touch-action: none` は押したあとの箱の中だけ。ページのスクロールを奪わない)。最後に「続きは PC で。リンクをコピー」。
- **実装**
  - 漢字は SVG(viewBox 0 0 109 109、KanjiVG と同じ)。線は `<path pathLength="1" stroke-dasharray="1" stroke-dashoffset="1">` にし、WAAPI で 1 画ずつ `stroke-dashoffset: 1 → 0`。
  - 時間割は純粋な関数 `strokeSchedule(lengths: number[], totalMs: number)` で、線の長さに比例して配り、画と画の間に 60ms。合計は**画数によらず 1,400ms 以内**(画数が多いほど 1 画が速い)。`src/lib/motion/stroke-schedule.ts` に置き、Vitest で確かめる。
  - 線の長さは `getTotalLength()` を effect の中で 1 回だけ読む(描画中に読まない)。
  - 照準は SVG の `<g>` を `transform` で動かす(`pointermove` を rAF で 1 フレーム 1 回にまとめる)。
  - 色ズレの縁は、同じ漢字の線を 2 本重ねて `transform: translateX(±1.5px)` を 0 → 1.5px へ 200ms(マゼンタとシアン、`mix-blend-mode: screen`)。
- **重さ**:JS 3KB 以内。SVG の線は 1 文字 2KB 前後(今日の 1 文字だけをサーバーで HTML に入れる。JSON 全体をブラウザに送らない)。
- **reduced-motion のとき**:漢字は描き終わった形で出す。照準とお試しのなぞりは残す(本人の操作なので)。色ズレの縁は最初から定まった形。
- **スマホのとき**:線の動きは同じ(短いので OK)。照準は出さない(ホバーがないため)。お試しは上のボタンを押したときだけ。

### S2. 診断 → 結果「12 行のマスが、あなたのタイプになる」

- **何を**:12 問と 12×12 のドット絵が同じ数なのを使う。
  1. 質問の画面の右上(スマホは進み具合の帯の上)に、12×12 の空のマスの小さな画面(96px)を置く。1 問答えるごとに 1 行が `--rl-line-strong` の色で点く(`steps(12)` で左から 120ms)。進み具合のバーの代わりではなく、横に添える(数字「3 / 12」と `role="progressbar"` は残す)。
  2. 最後の 1 問に答えると、12 行が上から順に**そのタイプのドット絵の色**に塗り替わる(1 行 30ms、合計 360ms)。
  3. 塗り替わった 96px の絵が、そのまま結果の画面の 160px(PC 240px)の TypeIcon へ**移って大きくなる**(View Transition の共有の要素、`name="type-sprite"`)。
  4. 結果の画面では、コード(ARCH)が 1 文字ずつ 40ms で出て、名前の色ズレの縁が一度だけ定まる。
- **実装**
  - マスの画面は `buildTypeSprite(code)`(Task 2)をそのまま使い、各行を `<g data-row>` にまとめる。点く・塗り替わるは WAAPI(`Element.animate`)で行ごとに `delay` をずらす。
  - 遷移は `router.push(url, { transitionTypes: ["type-reveal"] })`。両方の画面で `<ViewTransition name="type-sprite" share="morph" default="none">`。`::view-transition-group(.morph)` を 360ms `steps(6)`(大きくなる動きもカクカクに)。
  - 結果のページは静的に作れるので先読みが効く。`DiagnosisClient` で最後の 3 問目あたりから `router.prefetch("/type/…")` はできない(コードが決まっていない)ため、**16 通りの `/type/[code]` を Link の先読みと同じ扱いで最後の 1 問の画面を出した時点で先読み**する(16 ページは静的で軽い)。先読みが間に合わないときは、ふつうに入ってくる動き(壊れない)。
  - 今の `rl-assemble`(480ms `steps(8)`)は、View Transition が動かなかったとき(対応しないブラウザ・直接開いた人)の代わりとして残す。
- **重さ**:JS 2KB 以内。足す通信なし(16 ページの先読みは HTML だけで数十 KB。スマホの節約モード `navigator.connection.saveData` のときは先読みしない)。
- **reduced-motion のとき**:行は点くが動かない(すぐ点く)。最後の塗り替えと移る動きはなし。結果はタイプの絵をそのまま出す。
- **スマホのとき**:マスの画面は 64px で質問の上の帯に。移る動きは同じ。

### S3. ページ遷移「スキャンラインで切り替わる」

- **何を**:ページの中身だけが、上から 4 段のマスで消えて、4 段で出てくる(古いブラウン管の書き換えのように)。ヘッダーと下のタブバーは動かない(場所の目印を残す)。深く入る・戻るは向きで分ける。
  - ふつうの移動:中身が `clip-path` で上から 4 段(`steps(4)`、出る 120ms・入る 200ms)。
  - 深く入る(`/types` → `/type/ARCH`、`/lobby` → `/lobby/[id]`、`/mouse` の候補 → 店ではない):`nav-forward` で中身が左へ 24px + 4 段。戻るは逆。
  - 共有の要素:`/types` と `/` の名簿のタイプの絵 → 結果の大きな絵(`name="type-${code}"`)。`/` の今日の漢字 → `/aim` の見出しの漢字(`name="today-kanji"`)。候補の札のタイプの絵 → プロフィールの絵(`name="player-${id}"`)。
- **実装**
  - `PageShell`(Task 5)の中に `<ViewTransition enter={{...}} exit={{...}} default="none">` を入れる。PageShell は各ページが使うので、ドキュメントの「各ページに置く」に合う。PageShell を使わないページ(`/aim` の全画面など)は付けない。
  - `SiteHeader` と `BottomTabBar` に `viewTransitionName`(`site-header` / `tab-bar`)を付け、`animation: none`。
  - 戻るリンク(`ChevronLeft` の「ロビーへ」など)は `transitionTypes={["nav-back"]}`。ブラウザの戻るボタンは型が付かないので、ふつうの 4 段だけ。
  - CSS は `globals.css` に 30 行ほど。JS は足さない。
- **重さ**:0KB(React と Next の中にある)。全体 400ms 以内。
- **reduced-motion のとき**:`::view-transition-*` の `animation-duration: 0s`。共有の要素も移らない(すぐ切り替わる)。
- **スマホのとき**:同じ。横へずらす量は 16px にする。

### S4. 照準のホバー「押せるものに、照準が合う」

- **何を**:押せるもの(主ボタン・`interactive` のカード・タブ・名簿のタイプ)にマウスが乗る、またはキーボードでフォーカスすると、その四隅に**L 字の角の印**(照準の枠)が外側 6px から 2px へ寄って止まる。色はシアン(押せる色の意味がさらに強まる)。カーソルそのものは変えない(使いやすさを落とさない)。
- 押したとき:角の印が 1px 内へ寄り、`active:translate-y-px`(設計書どおり)。
- チップを選んだとき:`Check` アイコンの線が `stroke-dashoffset` で 120ms で引かれる(線の言葉)。
- **実装**:CSS だけ。部品のクラス `rl-lock` に `::before`(上の 2 つの角)と `::after`(下の 2 つの角)を `background` の `linear-gradient` 8 本で描き、`inset` ではなく `transform: scale()` で寄せる(`steps(2)`、120ms)。`:hover` は `@media (hover: hover)` の中だけ。`:focus-visible` でも同じ印を出す(フォーカスの線は設計書どおり残す。印は足すだけ)。
- **重さ**:CSS 1KB。JS 0。
- **reduced-motion のとき**:寄る動きをなくし、印がすぐ出る。
- **スマホのとき**:ホバーはない。押している間(`:active`)だけ印が出る。
- 注意:1 画面に印が出るのは常に 1 つ(マウスの下かフォーカスの所)。カード全部が光ることはしない(設計書のアンチパターン 16 と同じ考え)。

### S5. 名簿の入場「16 タイプがロビーに集まる」

- **何を**:トップの 16 タイプの名簿と `/types` の格子が、画面に入ったとき**一度だけ**、1 体ずつ 4 段の `clip-path` で現れる(左上から右下へ 30ms ずつ。合計 600ms)。サイトで「スクロールで動く」のはここだけ。
- 名簿の上にマウスを置くと、そのタイプの軸の 4 文字が下に 1 行で出る(例:「攻め・直感・チーム・熱血」)。名簿で軸が読める(Content の点にも効く)。
- **実装**:CSS の `animation-timeline: view()` が使えるブラウザはそれで(JS 0)。使えないブラウザは `IntersectionObserver` で 1 回だけ `data-in` を付ける(0.5KB)。どちらも `@supports` と `matchMedia` で分ける。
- **重さ**:JS 0.5KB。
- **reduced-motion のとき**:最初から全部出す。
- **スマホのとき**:同じ(4 列なので 1 行ずつ)。ホバーの軸の文は出さない(名前の下に最初から軸の 1 文字ずつを出す)。

### やらないこと(見せ場を薄めないため)

- マウスの後ろを追う光の点、カーソルの置き換え、全画面のパーティクル、背景が流れ続けるグラデ、スクロールで画面が固定されて進む演出、数字が毎回ぐるぐる回る演出(結果の点数の 1 回だけは可。下の 6 章)。
- 音(自動で鳴らない。将来入れるなら本人が押してから)。

## 4. 文字組み

### 4-1. 方針

- 見出しは**大きく、少なく**。1 画面で一番大きい文字と、本文の差を 6 倍以上にする(今は 40 / 16 = 2.5 倍)。
- 大きな文字は 2 種類だけ:**漢字 1 文字**(線の言葉)と、**Orbitron の数字・コード**(マスの言葉)。日本語の長い見出しを巨大にはしない(読みにくく、ゲームのサイトでありがちな形になるため)。

### 4-2. 段階の追加(表示用)

今の 12 / 14 / 16 / 20 / 24 / 32 / 40px はそのまま。上に表示用を 4 段足す。すべて `clamp()` で 375px → 1440px の間をなめらかにつなぐ。

| トークン | スマホ(375) | PC(1440) | `clamp()` の値 | 行間 | 使う所 |
|---|---|---|---|---|---|
| `--rl-text-display-1` | 56px | 72px | `clamp(56px, 50.4px + 1.5vw, 72px)` | 1.0 | 結果のコード(ARCH)、振り向き cm、`/aim` の点数、診断の始める画面の「12」 |
| `--rl-text-display-2` | 72px | 120px | `clamp(72px, 55.1px + 4.51vw, 120px)` | 0.95 | `/mouse` の 1 位の順位の数字、404 |
| `--rl-text-display-3` | 120px | 160px | `clamp(120px, 105.9px + 3.76vw, 160px)` | 0.9 | `/aim` の見出しの漢字 |
| `--rl-text-hero` | 160px | 280px(PC のトップだけ `min(56svh, 440px)`) | `clamp(160px, 117.7px + 11.27vw, 280px)`、1024px 以上のトップのヒーローは `--rl-text-hero-lg: min(56svh, 440px)` | 0.85 | トップのヒーローの漢字だけ |

- 設計書の「表示用 96(スマホ 72)」は、この表に置き換える。
- `--rl-text-hero` の漢字は SVG の線なので、文字の読み込み待ち(フォント)が起きない。
- (2026-10-02 トップの 2 回目の採点で追加)PC(1024px 以上)のトップのヒーローは、最初の画面いっぱいのヒーローの中で漢字が小さく見えるため、箱を画面の高さで決める `--rl-text-hero-lg`(`min(56svh, 440px)`。900px の画面で 440px)にする。色ズレのずれは 3px のまま(SVG の単位を 1.2 → 0.75 にする)。

### 4-3. 書体の役割の強化

| 書体 | 足すこと |
|---|---|
| Orbitron | **可変の太さ**にする。`next/font/google` で `weight` を書かずに読み込むと、400〜900 の 1 ファイルになる(今の 700/900 の 2 ファイルより軽いか同じ)。表示用の数字は 800、コード(ARCH)は 900、ROBILAB のサブロゴは 600 + 字間 0.08em。数字は `font-variant-numeric: tabular-nums`。押したとき・選んだときに太さを 700 → 900 へ 120ms で変える(Orbitron の数字のチップだけ。`font-variation-settings` は使わず `font-weight` の transition で)。 |
| Zen Kaku Gothic New | 可変ではない(400 / 500 / 700 / 900 の別ファイル)。足さない。役割:本文 500、見出し 700、ロゴとヒーロー横の 1 行(「今日の文字」)だけ 900。見出しには `font-feature-settings: "palt"` を付けて仮名を詰める(効かないときは `letter-spacing: -0.01em`。ブラウザで確かめる)。 |

### 4-4. 和文と欧文の組み

- **数字 + 単位**:数字は Orbitron(表示用の段)、単位は Zen Kaku 700 で数字の 0.4 倍、下のライン(ベースライン)にそろえ、間は 0.15em。例:「34.6」72px + 「cm」28px。単位をマゼンタにしない(数字だけマゼンタ、単位は `--rl-text`)。
- **コード + 名前**:ARCH(Orbitron 900、display-1)の下に名前(Zen Kaku 700、32px)。左の端をそろえる。コードの字間 0.04em。
- **縦組みは 1 か所だけ**:トップと `/aim` の漢字の右に、`writing-mode: vertical-rl` で「今日の文字」と日付・画数(Zen Kaku 700、20px / 14px)。書道の落款のような位置。数字(画数・日付)は `text-combine-upright: all` で縦の中の横組み。ほかの場所では縦組みを使わない。
- 英字のサブ(ROBILAB)はロゴの組みの中だけ。見出しの上の英字の札はやめたまま。

### 4-5. 色ズレ(D29)の使い方の決まり

- 付けるのは 3 か所だけ:ロゴ、ヒーローの漢字の縁(描き終わり)、結果のタイプの名前。
- 32px 未満の文字には付けない(にじんで読めない)。
- ずれは横だけ 1.5px(32〜72px)/ 3px(120px 以上)。止まった形。

## 5. レイアウトのリズム

### 5-1. グリッド

- PC(1024px 以上):幅 1120px に **12 列**(列の間 24px)。左右の余白は 1440px で 160px。
- タブレット(768〜1023px):8 列。スマホ:4 列(列の間 16px、左右 16px)。
- **8px のマス**が縦のリズムの単位。行間・余白・部品の高さはすべて 8 の倍数(44px のタップの大きさだけ例外。中の余白で 48 に合わせる)。
- 背景に 8px の点の格子(`radial-gradient` の 1px の点、白 4%)を、ヒーローと名簿の帯の 2 か所だけ敷く。マスの言葉が地にもあることを、近づいたときだけ感じさせる。

### 5-2. 余白の緩急

設計書の「セクションの間 48(スマホ 32)」を、強さで 3 段に分ける。

| 種類 | スマホ | PC | 使う所 |
|---|---|---|---|
| 間(ま)・大 | 96px | 160px | ヒーローのあと、1 ページに 1 回 |
| 間・中 | 64px | 96px | 話題が変わるセクションの間 |
| 間・小 | 32px | 48px | 同じ話題の中のまとまりの間 |

- 「大」は 1 ページに 1 回だけ。全部を広げない(間延びする)。

### 5-3. カードに頼らない構成

- 箱(Card)を使うのは「同じ種類のものの一覧で、押すと別の所へ行くもの」と「入力のまとまり」だけ。
- 代わりに使うもの
  - **幅いっぱいの行**:上下に `--rl-line` の線を引いた行。左に大きな見出し(32px)、右に `ChevronRight`。トップの 3 つの入口、相性のいいタイプ、`/my` の項目の見出し。
  - **名簿**:箱なしの絵 + コード。トップと `/types`。
  - **札**:ロビーの候補だけは「プレイヤーの札」として箱を残す(ロビーの言葉に合う)。
- 非対称:ヒーローは 12 列のうち 7 列に漢字、5 列に文字と行動。結果は 5 列に絵、7 列にコード・名前・説明。左右を毎回入れ替えない(読みの流れを守る)。

### 5-4. セクションの切り替え

- **マスの段差**:ヒーローの下の境目だけ、8px の階段の形の SVG(高さ 24px)で地の色が切り替わる(ヒーローの地は `--rl-bg` に点の格子、下は `--rl-bg`)。ほかの境目は線 1 本か、間だけ。
- **帯**:名簿の 16 タイプは、幅いっぱい(ページの幅の外まで)の `--rl-surface` の帯に乗せる。ページの中で 1 回だけ幅を破ることで、リズムが生まれる。

## 6. 画面ごとの「賞の水準」への差分

設計書 3 章に足すこと。書いていないことは設計書どおり。

### トップ(`/`。設計書 3-1)

- ヒーローを Card `feature` の箱にしない。箱なしで、地に点の格子。7 列に S1 の漢字(`--rl-text-hero`)、右に縦組みの「今日の文字」と日付・画数、5 列に「書き順どおりになぞるエイム練習」と今日の 1 位の点数(display-1 の Orbitron、マゼンタ)と主ボタン。
- ヒーローのすぐ下に h1(ロゴの組み:カタカナ 900 の 56px + ROBILAB)と 1 行の説明。ここで「間・大」。
- 3 つの入口は、カード 3 枚ではなく**幅いっぱいの 3 行**(5-3)。各行に小さなドット絵の絵(診断 = フラスコのドット、感度 = 定規のドット、仲間 = 3 人のドット。16×16 の格子をコードで描く)。lucide のアイコンは 20px で補助に残す。
- 16 タイプは S5 の名簿の帯。
- 足すもの:一番下に「今日の 1 位」と「きのうの文字」の小さな記録(Content。データがないときは行ごと出さない)。

### 診断(`/diagnosis`。設計書 3-2)

- 始める画面:左に「12」(display-1、Orbitron 800、マゼンタ)+「問」、「約 1 分半」、「16 タイプのどれか」。右に 12×12 の空のマス(S2 の画面の大きい版、160px)。「この 12 行が、あなたのタイプの絵になります」と 1 行。
- 質問の画面:S2 のマスの画面。答えのボタンに S4 の照準。押したあとの 200ms は選んだ見た目(設計書)+ その行が点く。
- 質問の文は 24px(設計書の 20px から上げる)。1 問 1 画面で余白が多いので、文を主役にする。

### 結果(`/type/[code]`。設計書 3-3)

- 上を 2 列(PC):5 列に TypeIcon 240px、7 列にコード(display-1)・名前(40px・色ズレ)・キャッチコピー。スマホは絵 160px を上に。
- 軸のバー(AxisBars)を**マスのバー**にする:10 マス(1 マス 8px の四角、間 2px)を % の分だけ塗る。表示時に `steps(10)` で 1 回だけ埋まる(S2 の続きの動きとして。reduced-motion なら止まった形)。
- 「この絵の読み方」を 1 行で:頭 = 攻め/守り、目 = 直感/戦略、体の横 = チーム/ソロ、色 = 熱血/冷静。絵の部分に細い引き出し線(線の言葉)を付ける(PC だけ。スマホは文だけ)。Content と Creativity の両方に効く。
- 相性のいいタイプは幅いっぱいの行(5-3)。絵の共有の要素で次の結果へ移る(S3)。
- シェアの画像のプレビュー(今の OG 画像)を、シェアのボタンの上に小さく出す。何がシェアされるか見える。

### 今日の文字(`/aim`。設計書 3-6)

- 見出しの漢字は `--rl-text-display-3`。トップから来たときは、ヒーローの漢字がそのまま移ってくる(S3 の `today-kanji`)。
- 開始のとき:遊ぶ面の真ん中に「3・2・1」(Orbitron 900、display-2、`steps(1)` で切り替え、各 600ms)。数字の切り替えは点滅ではなく置き換え(光の点滅にしない。明るさを変えない)。reduced-motion でも数は出す(ゲームの合図なので)。
- 終わったとき:書いた線がそのまま残り、お手本の線と重なって見える(ずれが分かる)。点数は display-1 で 0 から 600ms で数え上げる(1 回だけ。reduced-motion なら最初から最終の数)。
- ランキング:1〜3 位の行は高さ 64px・点数 32px、4 位からは 48px・20px。自分の行は `--rl-selected` の枠。最下位の強調はしない(アンチパターン 11)。
- 連続日数は `Flame` の代わりに 8×8 の炎のドット(マゼンタ)。数字と並べる。

### マウス探し(`/mouse`。設計書 3-7)

- **実寸の図**を主役にする:手の設定のすぐ横に、自分の手の輪郭(長さ・幅から作る SVG、線の言葉)の上に、1 位のマウスの形(長さ・幅の四角を角丸で)を同じ縮尺で重ねる。候補を選ぶと重なりが 200ms で入れ替わる。数字だけより一目で「合う」が分かる(Creativity と Content)。
- 1 位は箱ではなく大きな行:左に「1」(display-2、Orbitron、マゼンタ)、真ん中に名前(24px)と理由、右に店のボタン。2 位からは今の MouseCard を小さめに。
- 寸法の数字は Orbitron + 単位の組み(4-4)。

### ロビー(`/lobby`。設計書 3-9・3-10)

- 未ログイン:流れの 3 段を**横の線でつないだ 3 つの点**(PC は横、スマホは縦)。点は 8px のマス、線は 2px。各段の文は設計書どおり。ロビーの「待合室の掲示板」に見せる。
- 候補は「プレイヤーの札」:左に TypeIcon 64(大きく)、右上に相性 %(display-1 の半分の 40px、Orbitron、マゼンタ)、名前、ひとこと。札の左の端に、タイプの色の 4px の縦のマス帯(どのタイプか遠くから分かる)。
- 札を押すとプロフィールへ。絵が移る(S3 の `player-${id}`)。
- プロフィール(`/lobby/[profileId]`):自分と相手の TypeIcon を左右に並べ、間に相性 %(display-1)。「なぜ合うか」の 1 行を絵の間の線の上に。出会い系に見せないため、顔写真・ハートは使わない(アンチパターン 9)。
- 成立のとき(`/lobby/inbox`):成立した行だけ、2 つの絵の間の線が 1 回だけ引かれる(線の言葉、300ms)。演出はそれだけ(「マッチ」の派手な演出はしない)。

### マイ設定(`/my`。設計書 3-8)

- 埋まり具合を**8 マスのバー**に(1 項目 = 1 マス)。数字「5 / 8」と並べる。
- 名刺のプレビューは、入力に合わせてその場で変わる。変わった所だけ 120ms `steps(2)` で書き換わる(明るさは変えない)。名刺が「組み上がっていく」感じを出す。
- 項目の見出しは幅いっぱいの行(5-3)で、埋まった項目は右に `Check`、まだの項目は「まだ」と文字で。

### 感度計算(`/tools/sensitivity`。設計書 3-5)

- 振り向きの答え(display-1 の「34.6」+「cm」)の下に、**実寸の定規**を出す:1cm ごとの目盛りの SVG を、振り向きの長さの分だけ横に引く(線の言葉)。画面の 1cm は機械によって違うので、上に「画面上の長さは目安です」(14px)。長さが画面より長いときは折り返さず、右端に `ChevronRight` のアイコンと「あと 12cm」の文字(矢印の文字は使わない)。
- 入力を変えると、定規が新しい長さへ 200ms で伸び縮みする(`transform: scaleX`、目盛りは `vector-effect: non-scaling-stroke`)。
- マウスパッドの大きさの目安(S・M・L の横幅)を定規の下に薄い線で(データがある分だけ)。Content に効く。

### 共通

- 404:「404」を display-2 の Orbitron、その下に 12×12 のマスが一部欠けたドット絵(コードで描く)。
- 読み込み中(Skeleton):明るさの変化の代わりに、8px のマスが 1 段ずつ点く形にしてもよい(重さが同じなら)。reduced-motion で止める。

### 8-2. チェックの手順(1 回分)

1. `npm run build` と `npm run start`(本番の形。コントローラーが行う)。
