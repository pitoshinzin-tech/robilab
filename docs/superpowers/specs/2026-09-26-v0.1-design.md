## 1. 目的と成功の基準

### 目的
「ゲームといえばロビラボ」の入口を作る。v0.1 では、3つの目的で来た人を受け止める。

| 目的 | 機能 |
|---|---|
| 自分を知る | 1分半の16タイプ診断 |
| 感度を合わせる | 感度計算ツール |
| 仲間を探す | 相互承認型のマッチング(18歳以上) |

### 成功の基準(v0.1 公開時)
1. 3つの機能が、スマホとPCの両方で最後まで動く。
2. X でシェアしたとき、タイプ別のカード画像が表示される。
3. 他人の Discord ID・生年月日が、正規の手順(相互 OK)以外で見えない。
4. 18歳未満はマッチングを使えない。
5. アフィリエイト枠が PR 表記付きで表示され、Amazon アソシエイトと楽天アフィリエイトに申請できる状態になっている。

## 4. 判定のしくみ

### 4-1. タイプ判定(D15・D34)
- 4つの軸:A 攻め/守り、B 直感/戦略、C チーム/ソロ、D 熱血/冷静。1つの軸に3問。
- 回答を点数にする。
  - とても当てはまる=+3、やや当てはまる=+1、あまり当てはまらない=−1、全く当てはまらない=−3
  - 逆向きの設問は、符号を反転する。
- 軸の合計は、3つの奇数の和なので**必ず奇数になり、0 にならない**。合計の符号で、その軸の文字が決まる。
- 軸の強さ = 合計 ÷ 9(−1〜+1)。4軸のバーの表示と相性の計算に使う。
- タイプコードの文字は、ライター担当の叩き台(`content/drafts/type-code.md`)をもとに本人が決める(実装の「データ入力」工程の前に確定させる)。

### 4-2. ロールとの相性(結果ページ)
- ロールごとに「向いている4軸の値」r = (rA, rB, rC, rD)(各−1〜+1)を持つ。
- ユーザーの値 u との距離 d = √Σ(uᵢ − rᵢ)²。最大値は 4。
- ロール相性(%)= round(100 × (1 − d / 4))
- おすすめゲームのランキング:ゲームごとに一番相性の良いロールの%で並べる。

### 4-3. 人と人の相性(マッチング一覧、D34)
2人の軸の値を u、v とする。軸ごとのスコアは 0〜1。

| 軸 | 考え方 | 軸のスコア | 重み |
|---|---|---|---|
| D 熱量 | 似ているほど◎ | 1 − \|u−v\| / 2 | 0.4 |
| A 攻め/守り | 補い合うほど◎ | 1 − \|u+v\| / 2 | 0.2 |
| C チーム/ソロ | 補い合うほど◎ | 1 − \|u+v\| / 2 | 0.2 |
| B 直感/戦略 | 少し補い合うほど◎(差が1のとき最大) | 1 − \|\|u−v\| − 1\| | 0.2 |

- 相性(%)= round(100 × Σ 重み × 軸のスコア)
- ひとこと理由:スコアが高い上位2つの軸から、定型文を組み立てる。例:「熱量が近く、攻めと守りで補い合える」
- 並べる前に、次の条件で絞り込む。
  - 同じゲームを1本以上遊んでいる
  - 遊ぶ時間帯が1つ以上重なる
  - どちらからもブロックしていない
  - 相手が利用中(停止・BAN でない)
  - 同じ年齢区分
  - 自分自身ではない
- どちらかが診断をしていない場合は相性を出さず、「診断すると相性が見られます」と表示する。並び順は登録の新しい順にする。

### 4-4. 感度計算
- eDPI = DPI × 感度
- 振り向き(cm)= 360 ÷ (DPI × 感度 × yaw) × 2.54
- ゲーム間の換算:換算先の感度 = 元の感度 × (元の yaw ÷ 換算先の yaw)
- yaw の値と対象ゲームは、リサーチ担当の結果(`research/sensitivity-yaw.md`)で、情報源が2つ以上一致したものだけを使う。
- v0.1 は腰だめ(hipfire)の感度だけを扱う。ADS やスコープの感度は扱わない。

## 5. データと安全(D35)

### 5-1. テーブル(Supabase / Postgres)

| テーブル | 主な項目 | 見られる人(RLS) |
|---|---|---|
| `profiles` | id(=auth ユーザー)、nickname、type_code、axes(4つの値)、games(ゲームとランク帯)、platforms、voice_ok、time_slots、bio(50字)、age_group(adult/teen)、status(active/suspended/banned)、created_at | ログイン中で、status が active、同じ age_group の人。ブロック関係にある相手は見えない。本人は自分の行を常に見られる |
| `private_info` | user_id、discord_user_id、discord_username、birthdate | **本人だけ**。birthdate は登録後に変更できない(トリガーで禁止) |
| `approaches` | id、from_id、to_id、status(pending/accepted/passed)、created_at、responded_at、seen_by_to、seen_by_from | 当事者の2人だけ。送る人は from_id が自分のときだけ作れる。返事(OK/パス)は to_id が自分のときだけ変えられる |
| `blocks` | blocker_id、blocked_id | blocker 本人だけ |
| `reports` | id、reporter_id、target_id、reason(age_fake/harassment/spam/dating/other)、detail(200字)、status(open/closed)、created_at | 作成だけできる。読むのは運営だけ(Supabase の管理画面) |
| `diagnosis_results` | id、type_code、axes、created_at | 匿名で作成だけできる。誰も読めない(集計は v1.0) |

### 5-2. データベース側で強制するルール
- **年齢**:登録時に birthdate から age_group を決める。v0.1 は adult(18歳以上)以外の登録を拒否する。
- **声かけの上限**:同じ人からの声かけは、日本時間の1日あたり10件まで。
- **重複の禁止**:同じ相手への pending の声かけは1件まで。
- **ブロックとの関係**:ブロック関係にある相手には声をかけられない。
- **期限切れ**:pending のまま7日が過ぎたものは、期限切れとして扱う。読むときに判定するので、定期処理は不要。
- **パスの見え方**:パスされた声かけは、送った側には「返事待ち」→「期限切れ」と同じ見え方にする。パスされたことは伝えない。
- **Discord ID を返す関数**:`get_partner_discord(approach_id)` は、呼んだ人が当事者で、かつ status が accepted のときだけ、相手の discord_username を返す。
- **通報後の扱い**:通報されると、相手の status が suspended になり、一覧から消える。運営が確認し、active に戻すか banned にする。嫌がらせ目的の通報を繰り返す人は、通報者側を停止の対象にする(規約に明記)。

### 5-3. Discord ログイン
- Supabase Auth の Discord プロバイダを使う。要求する権限は `identify` だけで、メールアドレスは受け取らない。
- discord_user_id と discord_username は、ログイン情報から自動で保存する(手入力させない。なりすましを防ぐ)。
- BAN は discord_user_id 単位で行う。同じ Discord アカウントでは再登録できない。

### 5-4. その他
- 秘密の情報(Supabase の service key など)は Vercel の環境変数にだけ置く。GitHub には上げない。
- NG ワード:ニックネームとひとことを保存するときに、NG ワードのリストと照合する。リストはデータファイルで管理する。
- 開発中は Vercel の無料プランを使い、公開と同時に Pro に切り替える。

## 6. ファイル構成(1ファイル1役割)

```
src/
  data/        questions.ts, types.ts, games.ts(ロールと向いている値), sensitivity.ts(yaw),
               affiliates.ts, ng-words.ts
  lib/         scoring.ts(回答→軸→タイプ), role-match.ts, people-match.ts,
               sensitivity.ts, share.ts, analytics.ts
  lib/supabase/ client.ts, server.ts(Supabase への接続)
  app/         上のページ一覧のとおり。type/[code]/opengraph-image.tsx(シェア画像)
  components/  ui/(shadcn), brand/(ロゴ、ノイズのタイトル、ドット絵のアイコン), lobby/(一覧カードなど)
supabase/
  migrations/  テーブル、RLS、トリガー、関数
tests/         Vitest(判定・相性・感度)、RLS のテスト
```

- **計算処理**(lib)は、画面から独立した純粋な関数にする。テストしやすくするため。
- **データ**(data)と**計算処理**を分ける。ゲームやキャラの追加は data を足すだけで済む。

## 7. エラー時の扱い

| 場面 | 動き |
|---|---|
| 診断で未回答 | 「次へ」を押せない |
| 存在しないタイプの URL | 404 → 診断へ誘導 |
| 感度計算の不正な入力 | その場で注意を表示 |
| 診断の記録に失敗 | 結果はそのまま表示する(記録だけあきらめる) |
| Discord ログインの中断・失敗 | 元のページに戻し、「もう一度ログイン」ボタンを出す |
| 18歳未満 | 登録を止め、開放予定を表示する |
| 声かけの上限・重複・ブロック | 理由を短く表示する |
| 停止・BAN 中のログイン | 利用できないことと、問い合わせ先を表示する |
| 通信エラー | 「もう一度試す」ボタンを出す |

## 8. テスト

- **Vitest**
  - scoring:64通り(4択 × 3問の組み合わせ)× 4軸で、引き分けがないこと。16タイプすべてに到達できること。
  - role-match:手計算の例と一致すること。
  - people-match:似ている/補い合うの向きが正しいこと。
  - sensitivity:リサーチ担当の検算例と一致すること。
- **RLS のテスト**(テスト用のユーザー2〜3人で実行)
  - 他人の private_info を読めない。
  - 相互 OK でない相手の Discord 名を取れない。
  - 11件目の声かけが拒否される。
  - ブロックした相手が一覧に出ない。
  - 18歳未満で登録できない。
- **実機**
  - スマホで「診断 → 結果 → X シェア」。
  - 2つのアカウントで「声かけ → OK → Discord 名が見える」。
  - X のカードの表示。
- 公開前に `npm test` と `npm run build` が通ること。
