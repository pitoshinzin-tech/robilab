## 1. 目的と成功の基準

**目的**
- ゲーマーが自分の設定を一度だけ登録すれば、ロビラボのツールが入力なしで動くようにする(裏方)。
- その設定を「名刺カード」にして、X でシェアできるようにする(見せる名刺)。
- 公開後の機能(プロ設定、マウス探し、エイム練習「今日の文字」)は、すべてこのマイ設定を土台にする。

**成功の基準**
- 診断 → マイ設定 → 感度計算が、数字の入れ直しなしでつながる。
- ログインしなくても使える。ログインすると、スマホと PC で同じ設定が出る。
- 名刺カードを画像で保存できる。ログインした人は公開 URL で X に大きいカードとして出せる。
- 公開されるのは決めた項目だけで、Discord の名前・ID などの個人情報は出ない。

## 2. 本人が決めたこと(2026-09-29)

| 論点 | 決定 |
|---|---|
| 最初に作る機能 | マイ設定(ほかの3つの土台) |
| 役割 | 裏方(入力の自動化)+見せる名刺(シェア用カード) |
| 保存 | ブラウザに保存。Discord でログインしたらサーバーに移して共有 |
| 項目 | 診断タイプ(自動)、DPI とゲームごとの感度、手の大きさと持ち方、使っているデバイス、好きなゲーム(最大6つ) |
| デバイス・ゲームの入力 | 候補から選ぶ+自由入力 |
| シェア | だれでも画像を保存できる。ログインした人は公開 URL も作れる(公開は本人がオン・オフ) |
| サーバーの保存方法 | 1人1件の設定データ(JSON)として保存する |

## 3. 画面と流れ(設計 1/4)

### 3.1 マイ設定ページ `/my`(新規)
1. **タイプ**:診断結果から自動で入る。未診断なら「診断する」ボタン。
2. **感度**:DPI と、ゲームごとの感度。対象は感度計算ツールと同じ `src/data/sensitivity.ts` の7タイトル。メインゲームを1つ選ぶ。
3. **手と持ち方**:手の長さ・幅(cm)、持ち方(かぶせ/つかみ/つまみ)。
4. **デバイス**:マウス・マウスパッド・キーボード・ヘッドセット。候補から選ぶか、自由入力。
5. **好きなゲーム**:最大6つ。候補から選ぶか、自由入力。
6. **名刺の表示名**:カードに出す名前(任意)。

入力はその場で自動保存する(保存ボタンなし)。ページの下に、名刺カードのプレビューと「画像を保存」ボタンを置く。

### 3.2 既存の画面とのつながり
- **診断の完了時**:タイプと4軸の値をマイ設定に自動で入れ、「マイ設定に登録しよう」への導線を出す。
- **感度計算ツール**:開いたときにマイ設定の DPI・感度を最初から入れておく。計算結果は「マイ設定に保存」ボタンで保存できる。
- **ヘッダー**:「マイ設定」を足す。

### 3.3 ログインした場合
- ページ内で「Discord でログインするとスマホと PC で共有できます」と案内する。
- ログインすると、ブラウザの設定がサーバーに引き継がれる。
- 「名刺を公開する」をオンにすると、公開 URL と X シェアボタンが出る。

### 3.4 マッチングとの関係
- マイ設定は、マッチング(18歳以上、プロフィール登録制)とは**別物**。
- ログインしただけでは、マッチングに登録されない。
- マッチングのプロフィールは今までどおり別に保存する。

## 4. データと保存・引き継ぎ(設計 2/4)

### 4.1 データの形(版 1)
```ts
type MySettingsV1 = {
  version: 1;
  updatedAt: string; // ISO 8601
  typeCode: string | null; // ^[AG][RB][CL][HZ]$
  axes: { attack: number; instinct: number; team: number; heat: number } | null; // 各 -1〜1
  dpi: number | null; // 50〜64000 の整数(感度計算ツールの DPI_MIN / DPI_MAX と同じ)
  mainGame: string | null; // SENS_GAMES の id
  sens: Record<string, number>; // SENS_GAMES の id → 各ゲームの min〜max
  hand: { lengthCm: number | null; widthCm: number | null; grip: "palm" | "claw" | "fingertip" | null };
  // 長さ 10〜25cm、幅 5〜15cm(小数1桁)
  devices: {
    mouse: DeviceRef | null; pad: DeviceRef | null; keyboard: DeviceRef | null; headset: DeviceRef | null;
  };
  favoriteGames: GameRef[]; // 最大6つ、重複なし
  cardName: string | null; // 1〜20字
};
type DeviceRef = { id: string } | { name: string }; // id は候補の id、name は自由入力(1〜40字)
type GameRef = { id: string } | { name: string };
```
- 読み込むときに版番号を見て、古い版は新しい版に変換する。
- チェックに通らないデータは初期状態に戻す(壊れたデータで画面を止めない)。

### 4.2 ブラウザ
- localStorage のキー `robilab:mySettings` に保存する。
- 使えない環境では、ページを開いている間だけメモリに持ち、「この端末には保存されません」と表示する。

### 4.3 サーバー
新しい表 `my_settings` を作る:

| 列 | 型 | 内容 |
|---|---|---|
| user_id | uuid PK | auth.users(id) を参照。退会(ON DELETE CASCADE)で一緒に消える |
| data | jsonb | MySettingsV1 |
| updated_at | timestamptz | サーバーでの更新日時 |
| public_slug | text UNIQUE NULL | 公開 URL 用のランダムな10文字(英数字)。非公開なら NULL |

- RLS:本人の行だけ SELECT できる。INSERT・UPDATE・DELETE のポリシーは作らない(関数経由のみ)。
- 関数(SECURITY DEFINER、`search_path` 固定、authenticated だけが実行できる):
  - `save_my_settings(p_data jsonb)`:形・範囲・文字数・NG ワード・候補 ID の形をチェックして upsert する。
  - `delete_my_settings()`:自分の行を消す。
  - `set_card_public(p_public boolean) returns text`:公開をオンにすると新しい slug を作って返す。オフにすると NULL にする。
  - `get_public_card(p_slug text)`:anon も実行できる。公開中のカードの表示項目だけを返す(4.4 の一覧)。
- 同じチェックを `src/lib/my-settings.ts`(画面側)にも置く。上限値が一致することをテスト(SQL の定義を読むテスト)で確認する。
- NG ワードは既存の `_has_ng_word` を使う(自由入力の名前と、表示名)。

### 4.4 公開カードで返す項目(これ以外は返さない)
typeCode、cardName、mainGame とその感度、DPI、eDPI、振り向き cm、持ち方、デバイス4つの表示名、好きなゲームの表示名。

手の長さと幅は、マウス探しでは使うが、公開カードには出さない。

### 4.5 ログインしたときの引き継ぎ
- ブラウザとサーバーの `updatedAt` を比べて、新しい方を採用する。採用した方で、もう片方を上書きする。
- サーバーに行がなければ、ブラウザの分を保存する。
- ログアウトしても、ブラウザの分は残す。

### 4.6 消し方
- **「設定を消す」**:ブラウザとサーバーの両方から消す。
- **退会**:既存の `delete_me` をマイ設定のページからも呼べるようにする。マッチング未登録でも動く(profiles がなくても条件に引っかからない)。マイ設定は CASCADE で消える。
- プライバシーポリシーに、マイ設定の保存項目・公開範囲・削除方法を追記する。

## 5. 名刺カードと公開 URL・安全面(設計 3/4)

### 5.1 カード
- 1200×630、ネオンの暗い背景。見た目の最初の案は Claude が作り、仕上げは本人が行う。
- 載せる内容:
  - タイプのドット絵、タイプコード、タイプ名
  - 表示名
  - メインゲームの感度・eDPI・振り向き cm
  - デバイス4つ、好きなゲーム、持ち方
  - 小さなロゴ
- 描画は `next/og` の ImageResponse を使い、診断結果のシェア画像と同じ仕組みにする。新しいライブラリは足さない。

### 5.2 画像の保存(だれでも)
- ルート `POST /api/card-image` を作る。本文に設定データを受け取り、形をチェックして PNG を返す。
- URL で呼べる GET は用意しないので、他人に見せる手段にはならない。
- 本文の大きさに上限を設け、チェックに通らなければ 400 を返す。

### 5.3 公開 URL(ログインした人だけ)
- `/c/[slug]`:`get_public_card` の結果だけで描画する。存在しない・非公開なら 404。
- 検索エンジンには載せない(`robots: noindex`)。
- `/c/[slug]/opengraph-image`:X に貼ると大きいカードで出る。
- ページにはカードと「自分も作る(マイ設定へ)」ボタンを置く。

### 5.4 安全面
- 公開するのは 4.4 の項目だけ。Discord の名前・ID、手の大きさ、4軸の細かい値は出さない。
- 自由入力(40字)と表示名(20字)は、DB 側でも文字数と NG ワードをチェックする。画面では文字としてだけ表示する。
- slug は推測されにくいランダムな10文字(62種類の文字)。オフにすると使えなくなり、再公開のときは新しい slug にする。
- 運営が問題のあるカードを非公開にする手順(`update my_settings set public_slug = null where ...`)を `docs/ops/moderation.md` に書く。

## 6. 候補データ・エラー時・テスト(設計 4/4)

### 6.1 候補データ(公式のロゴや画像は使わず、名前だけ)
- `src/data/devices.ts`
  - 中身:マウス約30、マウスパッド・キーボード・ヘッドセットは各約15
  - 項目:`{ id, category, brand, name }`
  - 今はこの項目だけを持つ。マウス探しに必要な項目(重さ・形など)は、マウス探しの設計で足す。
- `src/data/popular-games.ts`:人気タイトル約40。`{ id, name }`。
- Claude がメーカー公式サイトなどで調べて最初の一覧を作り、本人が確認する。
- 候補の id は `^[a-z0-9-]{1,40}$`。DB 側は形だけをチェックし、一覧との一致は見ない(候補を増やすたびに migration が要らないようにする)。
  - 未知の id は画面で表示しない(自由入力の抜け道にしないため)。

### 6.2 エラーのとき
| 状況 | 動き |
|---|---|
| localStorage が使えない | メモリで動かし、「この端末には保存されません」と表示 |
| サーバーに保存できない | ブラウザには保存し、「サーバーに保存できませんでした」と表示。次の変更で再送する |
| NG ワード・文字数オーバー | その入力欄の横に理由を表示し、その欄だけ保存しない |
| 存在しない・非公開の公開 URL | 404 |
| カード画像を作れない | 「画像を作れませんでした」と表示 |

### 6.3 テスト
- **単体(Vitest)**
  - 入力チェック(範囲・文字数・重複)
  - 版の変換
  - 壊れたデータの読み込み
  - 引き継ぎの規則(新しい方を採用)
  - 画面側と DB 側のチェックの上限値の一致
  - 公開カードの表示項目の組み立て
- **RLS(dev)**
  - 他人の my_settings は読めない
  - `save_my_settings` が範囲外・NG ワードを弾く
  - `get_public_card` は公開中だけ・決めた項目だけを返し、anon でも使える
  - 公開をオフにすると古い slug は使えない
  - 退会すると my_settings も消える
- **手での確認**:スマホでの入力、X でのカード表示、ログイン前後の引き継ぎ
- **公開前**:差分のセキュリティ監査(`public-web-security-gate`、quick)を行う。
