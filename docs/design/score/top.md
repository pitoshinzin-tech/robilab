### 動き(コードから)

- S1:`KanjiStrokes` が CSS の `stroke-dashoffset` で 1 画ずつ引く。時間割はサーバーの `strokeSchedule` で合計 1,400ms 以内。描き始めの丸い端を `opacity` 0→1(1%)で隠しているのは丁寧。光(`drop-shadow`)は動かさず、重ねの `opacity` だけ動かす。決まりどおり。色ズレの縁は描き終わりから 200ms で 0 → 1.2 単位(280px で約 3px)。点滅しない。照準は rAF で 1 フレーム 1 回。JS の動きはなく、軽い。
- S5:IntersectionObserver で 1 回だけ `data-in`。`steps(4)` の `clip-path`、30ms ずつ・16 体で約 600ms。ハイドレーションの時点で 2 割見えていれば動かさない。sessionStorage で戻っても再生しない。reduced-motion は最初から出す。決まりどおり。
- 動きの設計そのものは 8.5 の水準。点を下げているのは「動きの前後の画面(静止の構成)」と「気づかせ方」。

## 2. 見つけた問題(重い順)

### 2-1. 375px の写真が 375px ではない(撮り方の問題。ソースの原因はなし)

- 写真では ROBILAB・説明文・入口の文・フッター・タブバーの 5 つめが右で切れ、名簿が 3 列×4 行に見える。
- ソースを見たが、375px で横にはみ出す要素はない。
  - ヒーロー:漢字の箱 160px(`--rl-text-hero` の最小)+ 縦組み約 50px。
  - 名簿:`grid-cols-4`、1 体 64px(48 + p-2)× 4 + 間 8×3 = 280px。中身の幅 343px に入る。
  - 入口:`grid-cols-[48px_minmax(0,1fr)_auto]` と `min-w-0`。h1 と フッターは `flex-wrap`。
- 理由:写真の数字が、画面の幅 500px とぴったり合う。
  - タブバー(`BottomTabBar.tsx:77`、`fixed inset-x-0`)は画面の幅そのものになる要素。その 5 列の間隔が写真で約 100px = 500 / 5。画面が 375px なら切れることはない。
  - 名簿の列の間隔が約 117px × 4 列 = 468px + 左右 16px×2 = 500px。
  - スマホでは出ないはずの主ボタン「今日の文字に挑戦」(`page.tsx:56`、`pointer-fine:inline-flex`)が出ている。スマホの扱い(タッチ)になっていない。
  - 新しい headless の Chromium(Edge)は、`--window-size` の横幅に下限(約 500px)がある。写真は 500px で描いたものを 375px で切ったもの。
- 直し方:撮り直す。`--window-size` ではなく、CDP の `Emulation.setDeviceMetricsOverride`(width 375, height 812, deviceScaleFactor 2, mobile true)と `Emulation.setTouchEmulationEnabled`(または Playwright の `devices["iPhone 13"]` に近い設定で viewport 375)を使う。撮ったら `document.documentElement.scrollWidth === 375` を記録に残す。これが通るまで Usability ④ は判定しない。

### 2-2. 空の「記録」の段(`src/app/page.tsx:129-148`)

- 今日の 1 位がないと、見出し「記録」と線だけの空の段が出る(PC・スマホとも写真で確認)。追補 6 章の「データがないときは行ごと出さない」に反する。空の状態に次にやることもない。
- 「きのうの文字」も出ない理由:`src/lib/aim/daily.ts` の `aimIndexForDate` は `AIM_START_DATE`(2026-11-01)より前は `Math.max(0, days)` で 0 になる。だから 11/1 までは今日もきのうも同じ字で、`yesterday.id !== char.id`(`page.tsx:141`)が必ず false。今日の 1 位がない日は、毎日この段が空になる。
- 直し方:どちらか。
  1. (おすすめ)段ごと出さない:`const hasRecords = top || yesterday.id !== char.id;` を作り、`{hasRecords && <section …>}` にする。
  2. 空の状態を作る:`top` がないとき 1 行目を「今日の 1 位 まだいません」+ `ButtonLink href="/aim" variant="secondary" size="sm"`「最初の記録を作る」にする(スマホは `/aim#ranking` へ)。
- あわせて、11/1 より前の「今日の文字」が毎日同じなのは、公開日を決めるまでの仮の状態として plan.md に一言書く(社長の判断)。

### 2-3. PC のヒーローの右半分が空く(`src/app/page.tsx:42-60`)

- 12 列のうち 7 列に漢字 280px + 縦組み(約 340px)、5 列に 20px の 1 行とボタンだけ。1 位がないと右の列はほぼ空。ヒーローの高さは約 430px で、900px の画面の下半分に h1 が見える。最初の 5 秒の画面が「スカスカ」に見える一番の原因。
- 直し方
  - 右の列を「今日の挑戦の札」にする。上から:20px の 1 行 → 遊び方の 3 行の箇条(例「1 画ずつ、書き順どおりに」「速さとずれで点数」「毎日 0 時に変わる」。各 16px、行頭は 8px のマス)→ 今日の 1 位(あれば display-1 の点数。なければ「今日の 1 位はまだいません」14px muted)→ 主ボタン。全部を 8 の倍数の間でそろえる。
  - ヒーローの高さを決める:`lg:min-h-[calc(100svh-64px-24px)]` のように最初の画面をヒーローで埋め、h1 を最初の画面から外す。または漢字の箱を PC で大きくする(下の 3 の P2)。
  - 左の列は `lg:justify-start` のままだと漢字の右に空きが残るので、漢字と縦組みを 7 列の中で右寄せ(`lg:justify-end lg:pr-12`)にし、右の札との距離を詰める。

### 2-4. 見出しの順が h2 → h1(`src/app/page.tsx:45`、`TodayLabel.tsx:215`)

- ヒーローの「今日の文字」が `TodayLabel as="h2"` で、ページで最初の見出しが h2。h1(ロビラボ)はその下。スクリーンリーダーの見出しの一覧で「ページの名前」が 2 番目に出る。
- 直し方:`TodayLabel` を `as="p"`(id はそのまま)にする。`aria-labelledby="today-heading"` は p でも効く。h1 がページで最初の見出しになる。

### 2-5. ヒーローと「ロビラボ」のタイトルの関係(情報の順。`page.tsx:66-73`)

- 今は「ヘッダーのロゴ(ロビラボ)→ ヒーロー → もう一度 72px のロビラボ」。初めての人は、何のサイトかを知る前に漢字を見せられ、そのあとに同じロゴを 2 回読む。h1 の段は左寄せで右が空き、ヒーローとも入口ともつながらない「浮いた帯」に見える。
- 直し方:h1 を「サイトの名前」ではなく「このページで何ができるか」の組みにする。
  - h1 の中身:`<span className="sr-only">ロビラボ — </span>` + 見える文は今の説明(`BRAND.lead`)を 32px 700 で。72px のロビラボ(`rl-glitch`)はやめるか、24px の ROBILAB と並ぶ小さな組みにする(ロゴはヘッダーにある)。
  - またはロゴの組みを残すなら、h1 の段を入口の段の「頭」にする:h1 と説明のすぐ下に入口の 3 行(間・小 48px)、h1 の前を「間・大」にする。今は h1 のあと 160px で、入口と切れている。
- どちらでも、色ズレ(`rl-glitch`)は 1 画面に 1 つにする(今は漢字の縁とロゴの 2 つが同じ最初の画面に入る。追補 2 章「見せ場は 1 画面に 1 つまで」の考え)。

### 2-6. 余白の緩急が「抜け」になっている

- 縦の間を足すと:ヒーロー pb-8 → 階段 24 → h1 pt-8 → **160**(`mt-rl-ma-lg`)→ 入口 → **96** → 名簿の帯 py-12 → **96** → 記録(空)→ フッター mt-12 + main pb-16(**112**)。空の記録を挟んで、下の 300px 近くが何もない。
- 「間・大」はヒーローのあとの 1 回と決めたのに、ヒーローと h1 の間は 32+24+32 で詰まり、h1 と入口の間が 160 で開く。強弱が逆。
- 直し方:`page.tsx:67` の `pt-8` を `pt-rl-ma-lg`(ヒーローのあとを大)、`page.tsx:76` の `mt-rl-ma-lg` を `mt-rl-ma-sm`(h1 と入口は同じ話題で小)。記録を出さない日は `main` の `pb-12 md:pb-16` を 0 にして、フッターの `mt-12` だけにする。

### 2-7. PC で S1 のお試しに気づけない(`HeroKanji.tsx:119-120`)

- PC では、なぞる前は案内の文が何も出ない(`min-h-11` の空いた場所だけ)。カーソルが十字になるのは漢字の上に来たときだけ。審査員の多くは気づかずにスクロールする。
- 直し方:`fine && !traced && !dragging` のとき「漢字をなぞってみる(ドラッグ)」を 14px muted で出す(場所は最初から取ってあるので CLS 0)。描き終わり(`--rl-drawn-at`)のあとに `opacity` で出すと S1 の流れに合う。サーバーの描画では `fine=false` なので、CSS の `[@media(hover:hover)_and_(pointer:fine)]:block hidden` で最初から出す形にする(今の「1 画なぞってみる」ボタンの逆)。

### 2-8. 見出しの大きさの上下が逆(`page.tsx:82, 93, 111` と `section-heading.tsx:252`)

- 入口の行の h2 が 32px、名簿と記録の h2(SectionHeading)が 24px。同じ h2 なのに、子の行のほうが大きい。`text-[32px]` は段階にある値だが、任意の値の書き方になっている。
- 直し方:入口の 3 行は `<section aria-labelledby>` の中の h3 にし(見出し「はじめる」などの h2 を sr-only で置く)、サイズは 32px のトークンの class に置き換える(例 `text-3xl` に相当する `text-rl-32` があればそれ。なければ globals.css の段階にそろえる)。

### 2-9. 名簿の帯が小さく空く(`page.tsx:121-125`、`TypeRoster.tsx:185`)

- PC で 48px の絵が 8 列×2 行。1,120px の幅に対して絵が小さく、帯の高さの半分以上が空き。ページで 1 回だけ幅を破る「帯」の力が弱い。
- 直し方:トップの名簿だけ `TypeIcon size={64}`(PC)にし、`showName` を付ける(名前が読めると Content にも効く)。帯の `py-12` を `py-rl-ma-sm`(48)のまま、`gap-y-6` に。スマホは 48 のまま。

## 2. 残っている問題(重い順)と直し方

### R2-1. 名簿の名前の切れ方(`src/components/brand/TypeRoster.tsx:54`、`src/app/page.tsx:146`)

- 1440:「先陣ヒーロータイ / プ」「突撃コマンダータ / イプ」など、16 体のうち 10 体以上が 2 行目に 1〜2 文字だけ残る。375:3〜4 行になり、行の高さもばらばら。
- 原因:列の幅(1440 で約 130px、375 で約 80px)に対して名前が長い。`wrap-anywhere` なので、どの文字の間でも切れる。
- 直し方(3 つ全部やる)
  1. 名簿では「タイプ」を付けない。`page.tsx:146` で `name: t.name.replace(/タイプ$/, "")`。見出しが「16 のゲーマータイプ」なので意味は通じる。読み上げ用の `sr-only` には元の名前を残す(`TypeRoster` に `label` と `name` を分けて渡すか、`sr-only` の文で `${t.name}` を使う)。
  2. `TypeRoster.tsx:54` の `wrap-anywhere` を `[word-break:auto-phrase] text-balance` にする(日本語の文節で切る。Chromium は対応していて、対応しないブラウザは今と同じ切れ方)。`lang="ja"` は `layout.tsx` にあるので効く。
  3. スマホは `text-xs`(12px)、`md:text-sm`。「サイレントハンター」が「サイレント / ハンター」の 2 行までに収まる。

### R2-2. PC のヒーローで漢字が小さく、真ん中に固まる(`HeroKanji.tsx:108`、`page.tsx:48-49`、`globals.css:69`)
